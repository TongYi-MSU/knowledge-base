# 自动备份型移动 SSD 与摄影充电宝一体化产品构想

> **状态**：概念设计与技术架构草案，尚无工程样机。本文只记录理念、功能设计、结构、功耗及原型路线；不包含商业、融资、ODM、价格、营销和专利策略。

## 一句话总结

制造一款**平时就是普通移动SSD，插入相机SD卡后自动把照片和视频备份到用户自装M.2 SSD**的设备；全程无须打开电脑、连接手机或操作App，利用内置电池独立完成。产品最初是极简自动备份硬盘盒，后进一步提出**20000mAh充电宝形态，兼具65W级USB-C充放电、移动SSD和插卡自动备份**。

## 核心知识

### 1. 产品问题与设计哲学

旅行拍摄中，“取卡 → 打开笔记本 → 接读卡器和移动硬盘 → 手动复制”的流程繁琐、设备多。希望把这一过程压缩为：

**取出相机卡 → 插入备份设备 → 指示灯显示复制/校验 → 绿灯完成 → 拔卡继续拍摄。**

核心理念：

- **只增加能力，不增加操作步骤**。产品不是便携NAS、个人云或智能手机配件。
- **一物多用**：日常是普通高速SSD；旅途中自动备份；20000mAh版本还是真正可用的移动电源。
- **用户自选SSD**：提供M.2 NVMe 2280插槽，用户可自主选择SSD容量、品牌和型号。
- **无屏幕、无Wi-Fi、无App、尽量无按键**；使用少量LED表达工作状态。
- **数据安全优先**：读取源卡时默认只读；不自动删除、格式化、覆盖原片。

### 2. 产品形态及型号

| 方向 | 形态 | 存储卡 | 电池 |
|---|---|---|---|
| Backup Mini（概念称谓） | 轻量化移动SSD硬盘盒 | 第一代SD UHS-I/UHS-II | 可探索5000–7500mAh |
| Backup Power（重点构想） | **20000mAh扁平充电宝**，自带SSD插槽 | 第一代SD UHS-II | **20000mAh** |
| 卡型衍生款 | 同样的软件/备份逻辑，不同读卡接口 | microSD/TF、CFexpress Type B，未来Type A | 根据体积和热设计决定 |

SD卡槽通过转接卡可兼容部分microSD卡，因此初版不必同时做TF独立型号。CFexpress Type B实际是PCIe/NVMe链路，速度潜力和功耗较高，不保证可以直接沿用SD版PCB。

讨论最终更重视**完整20000mAh充电宝形态**：它可替代原本单独携带的充电宝、外置SSD硬盘盒和SD读卡器。产品外形是充电宝，而最关键的新交互仍然是“插卡即备份”。

### 3. 初步技术指标：均为目标，不是实测

| 项目 | 目标与约束 |
|---|---|
| 固态硬盘 | M.2 NVMe，优先2280，用户自行加装 |
| 存储卡接口 | SD UHS-I/UHS-II；其他卡型分产品型号 |
| 电脑连接 | USB-C，目标USB 3.2 Gen 2 10Gbps级移动SSD模式 |
| 独立备份 | 不连接电脑或手机，插卡自动唤醒并复制 |
| SD实际备份速度 | 初步目标150–250MB/s，取决于卡、主控和SSD |
| 主力电池 | 20000mAh（按3.7V约74Wh） |
| 移动电源 | 目标USB-C PD 65W级输入/输出；具体接口和并发模式待设计 |
| 显示 | LED状态灯，无屏幕 |
| 文件系统 | 候选exFAT，需对PC模式、异常卸载与SSD写入行为进行验证 |
| 构造 | 扁平机身，SSD可拆，电池不得暴露于SSD拆装区 |
| 电池散热 | SSD、SoC等热源与电池做热隔离，外壳承担主要散热 |

接口标称10Gbps不等于能达到10Gbps的实际文件吞吐；“150–250MB/s”也不是承诺值。

### 4. 核心硬件架构问题

普通USB–NVMe硬盘盒中的桥接芯片只负责电脑USB与SSD的协议转换，通常不负责独立识别文件系统和复制相机卡。因此需要一个能够运行备份逻辑的主控。

**方案A——单SoC控制SSD**：存储卡读卡器 → SoC → SSD；PC接入时，SoC以USB设备模式对外提供存储服务。优点是易于先验证备份逻辑；缺点是PC数据速度、USB设备模式、功耗及软件复杂性需要检验。

**方案B——高速USB–NVMe桥接+独立备份主控+互斥切换**：PC模式经过专用桥接器，离线模式由内部主控接管SSD。理论上更容易保持高速硬盘盒的典型使用体验，但需要处理PCIe/USB连接切换、设备枚举、文件系统同步、电源瞬态。

**硬性要求**：同一SSD不能在PC和内部主控之间出现未经协调的并行写入；模式切换前必须完成同步、卸载与访问仲裁。

开发验证可先借助Linux SoC（例如RK3568类开发平台），量产选型再比较低功耗SoC、MCU组合或专用脱机复制控制方案。仅凭“MCU功率更小”不能断言每GB能耗更低，太慢会让设备运行更久。

### 5. 内置电池与USB-C电源行为

用户确认**内置供电不可妥协**。设计需支持：

1. 不接外设时，通过内置电池自动备份；
2. 插入笔记本后，既能作为USB移动SSD使用，也能在供电能力允许的条件下从笔记本汲取电量并充电；
3. 通过充电器或普通充电宝为机内电池充电；
4. 20000mAh版本还能对外提供USB-C PD快充；
5. 外部供电连接/拔出时，不应造成SSD写入中断。

这里需要**电源路径管理（Power Path）与USB-C数据/供电角色协商**。笔记本USB-C实际供电能力并不总是65W；如果只有有限电力，需要优先维持数据系统，剩余才给电池充电，必要时用内置电池补充供电。一个USB-C接口同时完成数据及各方向供电的复杂度较高；量产是否使用两个C口暂未确定。

对外充电与自动备份之间可能需要电量保留策略，但具体阈值未定。不能在没有热、安全测试的情况下自行制作20000mAh电芯包。

### 6. 电池容量与续航的计算

瓦时Wh比单独的毫安时mAh更适合表述能量；必须指定电芯电压：

$$E_{\mathrm{Wh}}=C_{\mathrm{mAh}}\times U_{\mathrm V}/1000.$$

若按3.7V标称电压：

- 5000mAh ≈18.5Wh；
- 10000mAh ≈37Wh；
- **20000mAh ≈74Wh**。

之前用于估算的示例：每天新增128GB照片与视频，SD实际复制速度150MB/s、复制时整机平均功率5W、连续7天。

$$t_{\mathrm{day}}=128000\mathrm{MB}/(150\mathrm{MB/s})\approx853s\approx14.2min.$$

$$E_{\mathrm{day}}\approx5\mathrm W\times853/3600\mathrm h\approx1.19Wh,\quad E_{\mathrm{7days}}\approx8.3Wh.$$

**注意：8.3Wh只是理想连续复制部分**。实际还需包含唤醒、校验、大小文件差异、转换损耗、待机、自放电、SSD品牌差异与安全余量。先前讨论过约5000mAh小电池版*可能*支撑该负载的一周，但并未实测；20000mAh方案有更宽裕的储能，不过如果同时给手机或笔记本充电，备份续航也会显著减少。

更有意义的研发指标是**每备份GB的能耗Wh/GB**：更快完成传输并真正掉电休眠，有时比低速低瞬时功率更省电。讨论中的休眠目标**小于1mW**（理想0.1–0.5mW），需要在系统中关闭SSD、主控和高速读卡器电源，只保留电源管理及插卡唤醒电路；尚无测试数据。

### 7. 自动备份状态机与文件可靠性

~~~mermaid
flowchart TD
 A["低功耗待机"] --> B{"检测到插卡？"}
 B -->|否| A
 B -->|是| C["唤醒主控、检测SSD与源卡"]
 C --> D{"容量及文件系统正常？"}
 D -->|否| X["错误指示，不声称备份成功"]
 D -->|是| E["只读挂载源卡，识别新增数据"]
 E --> F["复制到SSD临时文件"]
 F --> G["同步、验证并提交文件/备份清单"]
 G --> H{"本批次均成功？"}
 H -->|否| X
 H -->|是| I["绿灯：备份完成，可拔卡"]
 I --> J["安全卸载、关闭高功耗电路"]
 X --> J
 J --> A
~~~

备份设计原则：

- 为每张卡/每次任务建立明确目录和清单，保留原始DCIM等目录结构；
- 再次插卡时只备份新内容，但不能只用文件名去重：相机格式化后可能重用文件名；
- 用临时文件和持久化状态记录避免半截文件被标为成功；
- 必须区别“文件已复制”“已同步到介质”“校验一致”三种语义；成功绿灯只能基于定义清楚的校验；
- 拔卡、掉电、SSD空间不足等故障后，设备下次应能识别未完成任务并恢复；
- **禁止自动删除或格式化源卡**，单块SSD不能替代第二份独立备份。

可讨论的LED交互：白色待机、蓝色复制、蓝色快闪校验、绿色成功、红色错误。无屏幕意味着颜色与状态必须易理解。

### 8. 工业设计与热设计

最早考虑沿用细长2280硬盘盒造型，把5000mAh软包电池叠放；但电池面积和散热会主导整个机身布局。20000mAh版本可以采用扁平充电宝造型，内部安排**电池包 / 供电板 / 数据板 / SSD及散热层**，不必为保持细长硬盘盒外形牺牲安全。

SSD采用用户可拆装的独立舱位；电池和高功率PD电路保持保护与隔离，SSD通过导热介质向机壳散热，避免将热量传递到电芯。机身尺寸、质量与充电散热上限均未定案，需要真实电芯、PCB与结构模型来决定。

### 9. 最小可行工程原型（PoC）

无需先研发完整充电宝系统，先在桌面验证**脱机存储功能**：

1. 使用现成开发板、外置SD读卡器、M.2 NVMe扩展/转接设备和现有成品充电宝供电，先避免裸电芯操作；
2. 实现插卡检测、源卡只读访问、复制、校验、任务日志、断点恢复和状态灯；
3. 记录速度MB/s、功率W、能耗Wh/GB、开机时间、关机待机电流；
4. 验证接电脑后普通移动SSD模式是否可用，尤其验证SSD访问权切换；
5. 然后使用成熟电池电源平台验证USB-C PD、外部供电切换、同时充电/备份与热负载；
6. 最后再做紧凑PCB、用户可装SSD的外壳与不同存储卡型号。

需要做的故障测试包括：复制中拔卡、突然掉电、低电量、SSD写满、相机格式化后重用文件名、换SSD、USB接入/断开以及电池温度升高。**能跑通演示不代表能安全可靠使用。**

## 适用范围与注意事项

- 所有速度、功率、续航、USB PD能力和小型化方案都处于假设与待验证阶段，不应作为成品说明书。
- 真实电池标称容量和航空运输规格必须以实际所用电芯、电池组标识及合规测试为准。
- 软件可以使用Linux原型，不要求最终成品运行完整Linux；最终芯片架构待实测确定。
- 本笔记**特意不收录**ODM、品牌竞争、专利布局、价格、量产资金或融资讨论。
