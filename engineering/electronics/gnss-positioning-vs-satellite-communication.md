# GNSS 单向定位与卫星通信：定位、回传、隐私及干扰的技术边界

## 一句话总结

**普通 GPS/GNSS 定位是卫星向用户接收机单向广播导航信号、接收机在本地解算位置的过程，不等于接收机与卫星建立双向通信。** 接收机知道自己在哪里，并不意味着卫星或导航系统地面控制段知道它在哪里；向外界实时报告坐标需要独立的通信链路。北斗短报文等业务是另行集成的通信服务，不能与普通 GNSS 接收混为一谈。

## 核心知识

### 1. GPS 与 GNSS 的范围

GNSS（Global Navigation Satellite System，全球卫星导航系统）为卫星导航系统的统称；GPS 是美国的一个具体系统，此外还有俄罗斯 GLONASS、欧盟 Galileo、中国北斗 BDS。多星座接收机能够综合使用多个系统的信号。

普通 GNSS 由卫星**单向广播**伪随机测距码、卫星时钟与轨道等导航数据。接收机自行完成信号捕获、跟踪、伪距测量与位置/速度/时间（PVT）解算。广播本身不要求为每名用户建立会话，用户数量不会按比例增加导航卫星的广播负荷。

| 问题 | 结论 |
| --- | --- |
| 手机 GNSS 定位必须有 SIM 卡或蜂窝信号吗？ | 不必；接收机有卫星视野、具备必要数据且能收到导航信号即可进行独立定位。 |
| 普通 GPS 接收机向 GPS 卫星发射自身坐标吗？ | 不会；常规民用 GNSS 定位是被动接收，不存在这种上行步骤。 |
| GPS 卫星或其地面控制中心能直接查询某台普通接收机位置吗？ | 不能仅通过 GPS 导航广播做到；系统并未收到接收机身份和坐标。 |
| 远程控制中心能看到终端实时轨迹吗？ | 可以，但需终端通过蜂窝网络、卫星通信、无线电数据链等额外渠道上传位置。 |
| 卫星导航系统完全没有双向无线电链路吗？ | 不是。卫星和地面运控之间另有测控链路；北斗还集成独立的短报文业务。不能把这些与普通 GNSS 用户定位信号混同。 |

### 2. 位置在接收机内怎样算出来？

接收机测量导航信号的传播延迟，利用已知卫星轨道/时钟信息形成伪距观测。简化模型：

\[
\rho_i = \|\mathbf r-\mathbf s_i\| + c(\delta t_r-\delta t_{s_i}) + I_i + T_i + \varepsilon_i.
\]

其中：

- \(\rho_i\)：第 \(i\) 颗卫星的伪距观测，单位米；
- \(\mathbf r=(x,y,z)\)：待求的接收机三维坐标，单位米；
- \(\mathbf s_i\)：由星历求得的卫星坐标，单位米；
- \(c\)：光速，约 \(2.9979\times10^8\,\mathrm{m/s}\)；
- \(\delta t_r\)、\(\delta t_{s_i}\)：接收机和卫星钟差，单位秒；
- \(I_i\)、\(T_i\)：电离层、对流层传播延迟折算为的测距项，单位米；
- \(\varepsilon_i\)：测量噪声、多路径及未建模残差等，单位米。

在常规独立三维定位中，至少需要四条独立且几何条件适当的伪距观测，才能同时求解 \(x,y,z\) 与接收机钟差。实际设备通常使用更多卫星和误差改正，定位精度还受卫星几何、遮挡、多路径、大气、接收机性能等影响。若引入已知高度或外部时间等约束，最少卫星数可以改变，故“四颗”不是所有模式下的绝对门槛。

**核心因果关系：卫星发送时间与轨道参考信息，接收机计算自己的位置；不是卫星观测某台手机后把手机坐标下发给它。**

### 3. 定位、位置上报和远程控制是三个独立功能

| 层次 | 典型技术 | 数据方向 | 作用 |
| --- | --- | --- | --- |
| 本地定位（PNT） | GPS / GLONASS / Galileo / 北斗 RNSS | 导航卫星 → 接收机 | 接收机生成自己的位置、速度、时间 |
| 位置回传（telemetry） | 蜂窝数据、Starlink、卫星短报文、专用无线链路 | 终端 → 通信网络 → 控制中心 | 上报坐标、告警、设备状态 |
| 远程下行控制 | 可用的双向通信网络 | 控制中心 → 通信网络 → 终端 | 下发指令、配置、控制信息 |

例如，偏远地区的终端可以使用 GNSS **本地定位**，再用 Starlink **将已算出的坐标传回**控制中心。此处 Starlink 解决的是通信覆盖或回传问题，而非 GPS 定位本身需要“连接 Starlink 卫星”。终端还须具备适用的通信设备、电源、覆盖和服务权限；Starlink 也非唯一方案。如果只传少量坐标数据，低速卫星数据服务或短报文系统可能更合适。

### 4. 互联网、A-GNSS 与离线定位

A-GNSS（辅助 GNSS）可通过网络提供粗略位置、时间、星历/辅助数据等信息，以缩短首次定位时间（TTFF）或改善特定条件下的获取过程。**辅助网络不等于导航信号本身**；没有 SIM 卡或互联网，具备 GNSS 接收能力的终端仍可能完成独立定位，但首次定位时间及成功率受环境与已有数据影响。

现代手机显示的“位置”还可能融合 Wi-Fi、蜂窝基站、惯性传感器、蓝牙等信息，因此应用获得位置不总意味着刚刚完成了纯 GNSS 解算。

### 5. “卫星会不会跟踪我”：隐私边界

单靠常规 GPS 导航广播，导航卫星不知道有哪些接收机正在监听，也不能识别某台设备的坐标。美国 GPS.gov 将 GPS 卫星描述为不能追踪地面目标的单向信标。

但**GNSS 自身不追踪 ≠ 搭载 GNSS 的设备不会泄露位置**。手机操作系统、获得权限的应用、运营商网络、车载追踪器、卫星通信终端等可能在独立的通信、记录或共享链路中处理坐标；应按具体设备与权限架构判断。GPS 地面控制段与导航卫星的测控通信，也不意味着普通接收机向其上传坐标。

### 6. 北斗短报文为什么不是反例？

北斗系统除常规广播定位功能外，还设计了短报文通信及位置报告等特色服务。支持相应业务的**特定终端**可以经通信链路发送消息，甚至回传位置信息；这并不是说任意具备北斗/GNSS 定位功能的手机都会把自己的坐标发给北斗卫星。

区分：

- **RNSS（无线电导航卫星业务）**：和普通 GNSS 一样依靠导航信号完成接收端定位。
- **短报文/相关通信业务**：另行具备上行通信能力，可支持消息或位置上报；依赖相应终端和业务条件。

这里讨论的“GNSS 是单向的”，严格指**常规用户导航信号链路**，而不是否定整个卫星系统所有其他链路的双向能力。

### 7. “GPS 位置阻塞系统”究竟是什么意思？

这个表述不是足够明确的工程功能定义，至少可能涉及四种不同需求：

| 想实现的效果 | 技术概念 | 与 Starlink 的关系 |
| --- | --- | --- |
| 阻止接收机获得可靠卫星定位 | GNSS 遮挡、干扰（jamming） | Starlink 不会替代或自动阻断 GNSS 射频信号 |
| 令接收机计算出错误的位置/时间 | GNSS 欺骗（spoofing） | 属于信号完整性问题，与普通位置回传无关 |
| 阻止某设备把已知坐标上传 | 通信链路、权限和信息流控制 | 要分析终端的上传渠道；与是否仍可本地定位是两件事 |
| 在无蜂窝覆盖区监测目标位置 | GNSS 定位 + 卫星通信回传 | Starlink 等可充当回传链路 |

技术判断上，**干扰会削弱/阻断真实导航信号；欺骗会使设备接受伪造导航信号而算错位置或时间**。两者都有安全和合法性风险，不能仅凭“阻塞”一词判断原方案究竟是哪一种。本笔记仅澄清原理，不提供实施射频干扰或欺骗的操作指南。

## 关键细节

### 常见逻辑错误

1. **“我能收到卫星信号，所以卫星能收到我发的信号。”** 不成立：接收能力不等于发射能力，GNSS 常规接收机没有与导航卫星建立用户上行链路。
2. **“没有蜂窝信号就不能 GPS 定位。”** 不成立：蜂窝通信可用于辅助定位与回传，但 GNSS 可独立工作。
3. **“导航系统知道我的位置，因此控制中心当然能查到。”** 前提错误：本地位置解算通常发生在用户接收机，控制中心要知道结果需要额外的信息上报路径。
4. **“GPS 是单向的，因而任何带北斗的设备都不能发卫星消息。”** 也不成立：导航链路和独立的卫星消息业务可以集成在同一产品中。
5. **“给 GPS 设备加 Starlink 就能实现 GPS 信号阻断。”** 不成立：通信回传与射频定位干扰属于不同技术层次。

### 一句话辨别系统架构

先问清楚三个问题：**谁测得位置？位置是否离开本机？通过哪条通信链路离开？** 对方如果不能回答这三点，就很可能把定位、跟踪、通信和控制混成了一个概念。

## 适用范围与注意事项

- 本文针对**普通民用 GNSS 接收机的常规定位服务**；不穷尽卫星测控、测距、救援通信或特定组合导航业务。
- “卫星不追踪接收机”是对 GNSS 导航信号机制的说明，不对手机应用、联网设备、运营商或其他监测机制做隐私保证。
- 本文的 GNSS 定位模型为简化伪距方程；实际解算还考虑相对论、天线偏差、地球自转、接收机硬件偏差、卫星钟改正等误差项。
- 对未经定义的“GPS 位置阻塞系统”只能做需求分类，**不能据截图直接判定其实际设计、意图或有效性**。
