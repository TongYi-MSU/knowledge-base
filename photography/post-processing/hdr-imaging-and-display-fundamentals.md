# HDR 成像与显示原理：从传感器动态范围到跨设备呈现

## 一句话总结

**HDR（High Dynamic Range，高动态范围）不是一种单独的色域、分辨率、位深度或摄影滤镜，而是一套围绕“更大亮度范围的采集、处理、编码、传递与显示”建立的技术体系。** 相机能够记录多大的场景动态范围，与屏幕能够呈现多大的物理亮度范围，是独立但相互关联的能力；专业制作的核心是通过色彩管理和色调映射，将已有信息按创作意图呈现出来。

## 核心知识

### 一、区分六个容易混淆的量

| 概念 | 定义 | 常见单位 / 标准 | 不能等同于 |
|---|---|---|---|
| 场景/传感器动态范围（Dynamic Range） | 一次记录中可区分的最强和最弱有效信号范围，弱信号端受噪声约束 | EV/档，信噪比条件 | 屏幕对比度 |
| 曝光宽容度（Exposure Latitude） | 曝光偏离目标后，仍可在可接受画质下后期调整的能力 | 通常以曝光档数描述 | 传感器理论动态范围 |
| 显示亮度（Luminance） | 屏幕发出的光的亮度 | nit = cd/m² | RAW 曝光值 |
| 显示对比度（Contrast Ratio） | 给定条件下亮区与暗区显示亮度之比 | 例如 1000:1；必须注明测量条件 | 峰值亮度本身 |
| 色域（Color Gamut） | 可表示/覆盖的颜色色度范围 | sRGB、Display P3、Rec.2020 | HDR |
| 色彩体积（Color Volume） | 色度范围与可实现亮度共同构成的三维颜色集合 | 随亮度、面板和映射改变 | 二维色域覆盖百分比 |

动态范围以曝光档数表示时，可写为：

- DR_EV = log₂(L_max / L_min)，其中两端必须采用同一种物理量和同一测量语境。
- 14 EV 表示约 2¹⁴ = 16384 倍的信号比值。
- “传感器 14 档”不能直接推出“标称对比度 16384:1 的显示器能够准确还原 RAW”，因为二者的测量对象、噪声/黑位条件、显示适应状态都不同。

**宽色域、10-bit、4K、高亮度、高动态范围互相关联但均不能单独证明 HDR 质量。**

### 二、HDR 的两个不同语境：拍摄合成与 HDR 交付

1. **高动态场景的采集（Scene-referred）**：相机 RAW 可包含远多于普通 SDR 成片最终呈现的亮度关系。若单张 RAW 的信噪比和高光容量不足，可使用包围曝光合成；若单张 RAW 已保留足够信息，则不必拍多张。
2. **HDR 显示与交付（Display-referred）**：创作者将画面映射到允许高于 SDR 参考白的显示亮度，并使用相应的 HDR 编码/元数据交付。
3. 二者独立：**多张包围曝光合成的照片可以导出为 SDR；单张 RAW 也可以制作成真正 HDR 显示照片。**

#### 两种“看起来过曝”

- **传感器真实剪切**：重要高光已饱和，RAW 中没有可恢复的纹理或颜色；换 HDR 显示器也不能恢复不存在的数据。还须区分单通道剪切与全部通道剪切。
- **显示或导出阶段的高光压缩/剪切**：RAW 有层次，但 SDR 渲染把高光压在一起，或直接剪切成白色。重新从 RAW 做 HDR 输出，可在兼容设备上恢复更宽的显示亮度层次和部分颜色表现。

重要修正：**SDR 并非无法显示 RAW 中的任何高光细节**。恰当的色调映射可以在 SDR 中保留大量高光与暗部纹理；代价是压缩原始明暗间的物理亮度差。HDR 的优势是能以更大的实际亮度差、较少的压缩来表达这些信息，而不是凭空增加采集的细节。

### 三、色调映射（Tone Mapping）的必要性

把场景亮度范围映射到目标显示能力，可概念化为：

L_display = T(L_scene; display_peak, black_level, viewing_environment, creative_intent)

其中 T 不是唯一固定函数；它可能压缩高光、抬/保暗部、调整局部对比，且受创作意图与设备限制影响。

- SDR 需要在相对有限的亮度范围内做更强压缩。
- HDR 仍需要色调映射：例如目标母版为 1000 nit、终端仅有 500 nit 峰值时，高光不能原样复现。
- **保留细节不等于把所有区域都提到中灰**。暗处可有纹理但仍很暗；亮处可有层次且仍然很亮。
- HDR 可增强现实感，也可服务于风格化创作；准确技术显示与审美取舍是两个判断。

关于如何避免全局压高光、提阴影造成灰平画面、以及局部曲线/Dodge & Burn 的实际方法，见[《HDR 后期：动态范围、局部对比与视觉层级》](hdr-tone-mapping-and-visual-hierarchy.md)。

### 四、色域、传递函数与 HDR 格式并不相同

| 名称 | 主要规定的内容 | 是否自动等于 HDR |
|---|---|---|
| sRGB、Display P3 | 色域和相关颜色编码特性 | 否 |
| Rec.709 | SDR 高清视频的色彩/信号标准族 | 否 |
| Rec.2020 / BT.2020 | UHD 视频广色域的三原色等参数（也可用于 SDR） | 否 |
| Rec.2100 / BT.2100 | HDR 电视图像的参数体系，采用 Rec.2020 三原色并规定 PQ 或 HLG | 是 HDR 体系 |
| PQ / SMPTE ST 2084 | 以绝对显示亮度为目标的电光传递函数（EOTF） | 是 HDR 核心亮度编码 |
| HLG | 相对亮度 HDR 传递方式，重视广播制作与不同显示环境的适配 | 是 HDR 核心亮度编码 |
| Log（如 S-Log3） | 相机素材采集/中间处理的对数编码 | 否，通常须进一步转换并制作成 SDR/HDR 输出 |

**PQ** 定义信号到绝对亮度的关系，数学设计覆盖至 10000 cd/m²；这不是现实屏幕必须达到 10000 nit 的要求。**HLG** 采用相对信号体系，实际显示还与设备的系统 Gamma、峰值亮度和观看条件有关。

常见交付格式可按基础关系理解：

- HDR10：PQ + 广色域信号 + 10-bit 基础形式，辅以静态元数据。
- HDR10+ / Dolby Vision：加入动态元数据或更完善的显示映射指导；不同设备支持情况依播放链而定。
- HLG：主要用于直播/广播等场景，通常不依赖 HDR10 式静态元数据。

### 五、位深度为何重要，但 10-bit 不是 HDR 的定义

8-bit 每通道有 256 个编码级；10-bit 为 1024 个，能显著减轻天空和光晕的色带风险。PQ 利用人眼亮度感知特性分配编码级，适合表达更宽的绝对亮度范围。然而：

- 10-bit SDR 完全存在。
- 8-bit + FRC 显示与原生 10-bit 面板不同，最终效果取决于具体实现。
- 文件位深、内部计算精度、接口信号位深与面板原生位深不能混为一谈。

### 六、亮度层级：参考白、峰值和黑位

- 传统 SDR 参考监视环境常以 100 cd/m² 为参考显示白；这不是一切 SDR 消费屏幕的物理上限。
- ITU-R BT.2408 在 HDR 制作中使用 **203 cd/m² 的 HDR Reference White** 作为一个重要锚点（例如扩散白/图形白的参考）；它不是所有 HDR 作品每个白物体的绝对规定。
- HDR 高光可以在合适的显示目标与创作意图下高于参考白很多倍；画面不要求整体“暴亮”。

示意：暗街道 1–10 nit、建筑几十 nit、参考白约 203 nit、路灯反射可到 800–1000 nit。**这些只是解释量级的创作示例，不是必须遵守的像素亮度表。**

### 七、为什么显示器的“峰值 1000 nit”不够说明能力

显示质量至少要联合考察：

1. **小窗口峰值亮度**（例如 2% / 10% 亮区）、**全屏持续亮度**与自动亮度限制（ABL）。
2. **黑位及同画面同时对比度**：局部高光亮时，阴影是否还能保持深黑且不过度牺牲细节。
3. **控光机制**：像素级发光通常在黑位和暗场无光晕上有优势；局部调光 LCD 可能在大面积持续高亮上有优势，但仍受分区光晕限制。
4. **PQ EOTF 跟踪**：应显示 400 nit 的代码值是否真的约显示为 400 nit，而非故意提亮或压暗。
5. **色彩准确与色彩体积**：高亮度时还是否保有足够饱和度，色度及白点是否准确。
6. **亮度稳定性、均匀性与校准能力**：尤其关系到视频参考监看。

不存在“对比度超过某个全球统一数字，就自动成为高品质 HDR”的定义。VESA DisplayHDR 是针对显示性能的认证体系；**能接收 HDR10 信号**与**有能力高质量、准确显示 HDR10**是两件事。

手机宣传的“数千 nit”常涉及高环境照度激发模式、小测试窗口或短时峰值；不能不注明测试模式和亮区面积，就直接与专业监视器的持续亮度比较。

### 八、不同屏幕的 HDR 能完全一样吗？

**不能保证；标准化的是信号解释，不是突破物理限制。**

假设一段 PQ 内容将某个高光定义为 800 nit：

- 能准确输出该亮度的显示器，在校准和观看条件相近时有望接近创作者的目标。
- 峰值仅 500 nit 的显示器必须映射或裁切高光。
- 即使两块屏幕都有 1000 nit 峰值，PQ 跟踪、黑位、局部调光、高亮饱和度、环境光和观看距离仍会影响观感。

动态元数据（例如 HDR10+ / Dolby Vision）能为不同场景提供更精细的适配指导，但不保证所有设备严格同观感。

跨设备色彩一致性来自**颜色管理**：内容的颜色描述、正确嵌入/解释的配置文件、设备特性文件、颜色转换与校准共同起作用。Apple ColorSync 是一种系统级实施方案；正确配置的 Windows 和专业显示器同样可以达到高准确度。相同 P3 色域覆盖不等于相同色准，更不等于相同 HDR 亮度。严格调色时应避免 True Tone、Night Shift 或不受控的动态画质增强改变参考条件。

色差 ΔE 也必须注明公式（如 ΔE2000）、平均/最大值、测试亮度与色域；HDR/WCG 还可使用 ITU-R BT.2124 的 ΔE_ITP 指标。**宣传“ΔE < 1”不是不看条件就成立的统一保证。**

## 从拍摄到观看：两条端到端链路

### 照片

场景 → 传感器 RAW / 必要时包围曝光 → 原始信息整理与显影 → HDR 影调决定 → 支持 HDR 的图像编码/元数据 → 兼容软件与操作系统 → 具备足够亮度/对比度的显示器。

单张 RAW 可以制作 HDR 照片。**Gain Map（增益图）** 能够提供基础 SDR 表示与 HDR 重建所需的额外信息，支持软件可根据终端能力重现不同动态范围。ISO 21496-1:2025 对数字摄影中的增益图及其动态范围转换元数据进行了标准化。带增益图的 JPEG 可使兼容 HDR 软件呈现 HDR，而不支持的应用回退到 SDR；具体文件布局、元数据支持及平台保留情况需要实际核验。

### 视频

场景 → 相机 10-bit Log 或其他高质量素材 → 输入色彩空间/传递函数解释 → 场景到显示的色彩管理和调色 → 目标 HDR（例如 Rec.2100 PQ）→ 适配元数据/编码 → 播放链 → HDR 监看。

**同一份 Log 素材既能做 SDR，也能做 HDR。** HDR 不意味着运算量必然远大于 SDR；更多取决于分辨率、帧率、编解码、调色复杂度和降噪。非 HDR 监视器仍能进行数值处理、查看波形和输出文件，但不能作为最终 HDR 视觉参考。正式母版制作需要匹配目标标准的监视与校准、信号输出和受控观察环境。

## 常见判断题与纠偏

| 判断 | 结论 |
|---|---|
| 相机 RAW 往往保留比 SDR 成片显示范围更宽的亮度信息？ | 通常是，但须结合实际动态范围、曝光与噪声 |
| SDR 上亮部“白掉”了，HDR 屏幕就一定能修复？ | 否：需要从保留信息的源文件重新制作 HDR；真实剪切不能恢复 |
| HDR 就是色域 Rec.2020？ | 否：色域和 HDR 亮度传递是不同维度 |
| 4K 视频必须用 4K HDR 显示器剪辑？ | 否：分辨率影响全幅 1:1 检视，不决定 HDR 数值处理能力 |
| 10-bit 或 HDR10 标签能证明屏幕 HDR 画质优秀？ | 否 |
| 只有高峰值亮度，没有低黑位也能完美 HDR？ | 否 |
| 色准高就足以制作专业 HDR 母版？ | 否：还需 EOTF、亮度稳定性、色彩体积、均匀性等 |
| HDR 取消了色调映射？ | 否：只是相对 SDR 增加了呈现亮度的余量 |
| 苹果不同屏幕上的颜色天然完全相同？ | 否：色彩管理提高可预测性，但色域、白点、亮度、HDR 容量与环境仍有限制 |

## 适用范围与注意事项

- 本文讨论的是**技术原理与工作流程**，不是显示器型号对比、购买攻略或设备价格清单。
- 传感器动态范围的实测值与亮度目标取决于条件，不能把示意值当作相机或显示器的实测规格。
- 显示器峰值亮度不等于可在所有窗口大小上持续保持的亮度，也不等于 PQ 跟踪准确。
- HDR10、HDR10+、Dolby Vision、HLG、HDR 照片及不同增益图实现，不保证在任意操作系统/浏览器/播放器上得到一致支持。
- 本文补足已有后期笔记的**信号、标准与显示基础**，不重复其局部影调和摄影审美操作指南。
